# Исключение для ванильного рывка копья

15.11.2026, база `a52a9a2`.

Исключение ранее выдавалось по `EntityExhaustionEvent` с причиной
`ENCHANTMENT_EFFECT`, если в руке было зачарованное копьё. Это зависело от голода:
Creative не обязан создавать такое событие; другие плагины также могут менять
расход голода. Наличие чар само по себе не подтверждало применение рывка.

Теперь источник — разрешённый `EntityLungeEvent` с положительной силой у игрока.
Обработчик MONITOR не изменяет событие, выдаёт прежнее общее окно импульса 1200 мс
и не создаёт отсутствующего UserData. Отменённый рывок, нулевая сила и выключенный
параметр исключения не дают. Старый обход через событие истощения удалён.

Настройка уже присутствовала в стандартном конфиге и сохраняется:

```yaml
mechanics:
  movement:
    lunge-exemption:
      enabled: true
```

В старом пользовательском конфиге отсутствие этого ключа тоже означает true.
Обязательная ручная миграция не требуется.

## Границы вывода

Это исправляет источник сигнала исключения. Это не доказывает, что Vesuvio блокировал
конкретный пользовательский рывок: в присланном отчёте STAB дошёл до Connection,
но EntityLungeEvent отсутствовал. Новый обработчик не может сработать на событие,
которого не было. Исходная проблема запуска Lunge остаётся отдельным расследованием.

В текущем main Creative/Spectator и полёт освобождаются через
EnvironmentSnapshot.isMovementExempt(); FlagReporter и PunishmentService не содержат
встроенного отката позиции. Это не проверка произвольного старого JAR только по имени
vesuvio-26.3.jar; правила наказаний могут содержать внешние серверные команды.

Java 25, Maven verify: 361 тест, без ошибок/пропусков. Пять новых тестов проверяют
выдачу окна без события истощения, пропуск Speed/Fly/Phase/StepUp по этому окну,
отменённый/нулевой рывок, выключенную настройку, отсутствие восстановления вышедшего
игрока и значение по умолчанию старого конфига. Живой Paper/Purpur не проверен.
