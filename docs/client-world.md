# Копия мира клиента — 2026-10-13

Модуль реализован независимо от GrimAC. Это ограниченная реплика блоков в памяти,
отдельная для каждого игрока с включённым `/vesuvio physics Ник on`.
Она подключена к существующему диагностическому симулятору и не выдаёт наказания.

## Поток данных

1. `ClientWorldPacketListener` на MONITOR разбирает исходящие `CHUNK_DATA`,
   `BLOCK_CHANGE`, `MULTI_BLOCK_CHANGE`, `UNLOAD_CHUNK`. Block-state IDs копируются
   из палитры пакета; mutable-массивы PacketEvents в реплике не сохраняются.
2. Память под данные ожидающего write-completion callback резервируется сразу.
   Затронутый чанк уже считается неопределённым. После callback отменённый пакет
   отбрасывается; остальные изменения попадают в очередь в порядке записи.
3. Раз в серверный тик задача ставится в outbound event loop соединения. Она
   закрепляет текущую очередь за новым ID и отправляет Ping после записей пакетов.
   Маркеры не берутся из глобального main-thread счётчика серверных событий.
4. Входящий Pong должен совпасть с первым ожидающим маркером. Только тогда
   соответствующие изменения применяются к подтверждённой реплике. Чужие ID
   ничего не подтверждают. Повторные и недавно отменённые собственные ID поглощаются
   без повторного применения. Ответ на более поздний маркер очищает недостоверную
   реплику, а не подтверждает пропущенные ответы.
5. Пакет движения получает неизменяемую локальную геометрию именно в момент
   получения. Последующие изменения мира не меняют этот снимок, пока задача
   симуляции ждёт в очереди. Изменение ревизии ближайших чанков прогревает историю.

Обслуживаются только нативные сервер/клиент 26.2. Палитры других протоколов не
подставляются под текущие global IDs. Имя блока и свойства декодирует PacketEvents;
формы рассчитывает собственный явный `BlockShapeRegistry`. Нет обращения к живым
`Block.getCollisionShape()` или `World.getBlockAt()` для геометрии симулятора.
Существующие старые проверки Vesuvio по-прежнему используют свой серверный snapshot.

## Клиентское предсказание блоков

`START_DIGGING`, `FINISHED_DIGGING` и установка/взаимодействие с блоком помечают
чанк блока и возможного соседнего места установки как неопределённые. Это учитывает
локальное предсказание клиента, которое может появиться раньше серверного изменения.
Изначально отменённый входящий пакет тоже требует осторожности: клиент уже мог
изменить свой мир. Собственное предположение «блок сломан» не записывается как истина.

`ACKNOWLEDGE_BLOCK_CHANGES` снимает только префикс предсказаний до указанного sequence
и тоже применяется после Pong. Если сервер отклонил действие без изменения блока,
подтверждение восстанавливает применимость старой авторитетной геометрии. При новых
неподтверждённых действиях участок остаётся неопределённым. Нет ответа в течение
5 секунд — копия очищается, требуется поступление новых чанков.

## Переходы и ресурсные ограничения

- Respawn/смена измерения очищает мир и ожидающие маркеры. Поздний Pong не возвращает
  данные предыдущего измерения. Обычный телепорт в том же мире сохраняет актуальные
  отправленные чанки; кинематическая история сбрасывается отдельно.
- Включение диагностики не выдумывает ранее отправленные чанки. Нужна настоящая
  отправка новых чанков — например, после дальнего RTP. После выключения античита
  пропущенные изменения не догоняются чтением серверного мира: реплика очищается.
- До 32 чанков на игрока; при вытеснении сохраняются ближайшие к последней известной
  позиции. Серверная позиция используется только как подсказка кешу при телепорте,
  а не как источник блоков или доказательство допустимого перемещения.
- До 8 МиБ block-ID данных подтверждённого мира и до 8 МиБ ожидающих данных,
  включая callbacks при backpressure; до 256 изменений/ожидающих callbacks,
  40 маркеров и 256 клиентских предсказаний. Общий heap больше полезных данных.
  Одновременно диагностика разрешена для четырёх игроков.
- Секции ограничены 64 на чанк. Однотипная секция хранит один ID, прочие — 4096.
  При одиночном изменении копируется только затронутая секция.
- Потерянный, вытесненный, ещё не подтверждённый чанк или неизвестная секция означает
  UNKNOWN, а не воздух. Обновление блока без исходного чанка не создаёт пустой чанк.
- После выхода игрока данные и активное наблюдение удаляются. Лимит форм локального
  снимка — 512; максимум 175 проверяемых позиций блоков.

## Проверено автоматически

Порядок нескольких пачек, неизвестные/повторные/запоздалые Pong, смена измерения,
выгрузка/повторная загрузка, разные миры двух получателей, отрицательные координаты,
неизменяемость сохранённых кадров, лимиты очереди и памяти, сохранение близких чанков,
неопределённость при локальном копании, подтверждение только префикса действий.
Есть тест палитры настоящего PacketEvents 2.13.0 для 26.2 и совместный прогон
реплики с симулятором на аналитической траектории ходьбы.

## Оставшиеся ограничения

Pong — маркер порядка обмена, а не криптографическое доказательство честности
клиента и не подтверждение конкретного клиентского физического тика. Атрибуты,
эффекты, поза и импульсы ещё не имеют собственной подтверждённой истории. Нет
реплики сущностей, collision для всех форм/версий, жидкостей, транспорта и элитр.
Известные жидкости/waterlogged-состояния и неизвестные формы пропускаются.
Скрытые от PacketEvents записи пакетов невозможно учесть этим слушателем.
Все эти ограничения сохраняют необходимость диагностического режима.

Живой Paper/Purpur 26.2 с BetterRTP пока не проверялся. Unit-тесты не проверяют
реальное расположение обработчиков Netty, модификации пакетов другими плагинами
или точный момент применения пакетов игровым потоком клиента.

Для согласования с API изучались сигнатуры и порядок callbacks PacketEvents 2.13.0,
включая перевод координат `EncodedBlock` в абсолютные координаты. Исходники/байткод
физики GrimAC, Vacan или Minecraft для реализации этой реплики не использовались.

## Фоновое построение геометрии

При получении пакета движения `ClientWorld.capture` фиксирует собственный массив
из 175 идентификаторов блоков, опорный блок, протокол и версию области. Снимок не
содержит изменяемых ссылок на мир. `Capture.build` разрешает формы и создаёт коллизии
уже в упорядоченной фоновой задаче игрока, вне блокировки копии мира. Обновление,
подтверждение или сброс мира после получения пакета не меняет этот снимок. Неизвестная
область остаётся неизвестной даже после последующей загрузки её чанков.
