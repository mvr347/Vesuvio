# Статический разбор Vacan

Изучен репозиторий `mvr347/Vacan`, commit
`0cf48d2d7a28072ef5ee90f599b999c8e088707c`, версия из `plugin.yml`: 4.0.3.7.
Репозиторий содержит обфусцированные `.class`, а не исходный Java-проект.
Анализ выполнен через `javap -p -c`; классы плагина не запускались.

Имена исходных файлов сохранились в метаданных байткода:

| Класс | Сохранённое имя | Наблюдения |
| --- | --- | --- |
| `implementation.b.a.h` | `IMSimulationSpeed.java` | Обращение к movement-speed attribute, расчёты отклонения ускорения, сообщение `simulation[accel]` |
| `implementation.combat.d` | `HitReach.java` | Раздельные проверки `hitbox_raytrace`, `simple`, `throughblocks` |
| `implementation.combat.killaura.a` | `KABackTrack.java` | Обход истории координат, накопление результатов в списке и оценка окна наблюдений |
| `implementation.combat.killaura.e` | `KillAura.java` | Настраиваемое разделение обнаружения для игроков и других сущностей |
| `implementation.c.a` | `BlockReach.java` | Отдельные ветви breaking/interact/place/raytrace и атрибут дальности взаимодействия |
| `implementation.c.b` | `FastBreak.java` | Разделение delay/breaks-per-second и учёт block-break-speed attribute |

Для Vesuvio полезны общие принципы: серверные атрибуты вместо фиксированных
предположений, разделение дальности и попадания луча, история координат и
накопление свидетельств. Реализация изменений в Vesuvio самостоятельная:
байткод/исходники Vacan в проект не перенесены. Числовые пороги другого античита
не доказывают корректность для Paper 26.2 и не использовались как эталон тестов.

Разбор не устанавливает полноту, качество или частоту ложных срабатываний Vacan:
для этого нужны воспроизводимые серверные испытания с реальными клиентами.
