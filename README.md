# Vesuvio — Paper/Purpur 26.2

Для сборки нужен JDK 25 (Paper API содержит классы Java 25), Maven 3.9.x.
Команда сборки и тестов: `mvn verify`. Готовый плагин: `target/vesuvio-26.2.jar`.

## Управление

Все команды ниже требуют `vesuvio.admin`.

| Команда | Поведение |
| --- | --- |
| `/vesuvio toggle` | Полностью переключить проверки и применение наказаний |
| `/vesuvio toggle on` / `off` | Явно включить / выключить античит |
| `/vesuvio punishment toggle` | Переключить наказания, сохраняя проверки, VL и уведомления |
| `/vesuvio punishment on` / `off` | Явно включить / выключить наказания |
| `/vesuvio status` | Показать состояние проверок, наказаний и очередь банов |
| `/vesuvio physics <игрок> on` / `off` | Включить / выключить диагностику независимого симулятора для игрока |
| `/vesuvio physics <игрок> status` | Ошибка предсказания, число сравнений, расхождений и пропусков |

В режиме `punishment off` не выполняются команды наказаний, кики, баны,
волны банов и отмена игровых действий проверками. Уведомления и записи нарушений
продолжают работать. Накопленный VL сохраняется: после `punishment on` новое
нарушение снова может привести к наказанию.

При смене любого переключателя очередь банов очищается, ранее отложенные действия
становятся недействительными. `/vesuvio reload` сохраняет состояние переключателей;
перезапуск плагина возвращает оба во включённое состояние. После полного включения
проверки получают короткий период восстановления координат и истории движения.

## Изменения проверок

- Пакетные задачи одного игрока выполняются последовательно. Timer измеряет время
  получения пакетов, а не время запуска фоновых задач.
- Телепортация/возрождение сбрасывают историю движения, скорость, Timer, импульсы и
  устаревшие боевые задачи. Отслеживается подтверждение конкретного teleport ID;
  неподходящее или повторное подтверждение не продлевает исключение.
  BetterRTP не требует отдельной зависимости: используются события и пакеты сервера.
- FastBreak использует `Block.getBreakSpeed(player)` из Paper вместо таблицы
  инструментов. Мгновенное разрушение и пакетная задержка учитываются отдельно;
  отмена копания и смена слота сбрасывают попытку. Снимки окружения обновляются после
  изменения соседних блоков. GhostHand проверяет видимость нескольких точек блока.
- Горизонтальная модель учитывает перенос скорости трением, доступное ускорение,
  направление предыдущего движения и серверный атрибут скорости. Необъяснимое
  движение накапливает отклонение; одиночный скачок не является приговором.
- Reach измеряет пересечение луча удара с историческими хитбоксами. Допустимая
  дальность учитывает атрибут игрока; пинг выбирает исторические кадры, а не умножает
  дистанцию атаки. Для флага требуется накопление свидетельств.
- Каждый удар хранит собственные координаты и поворот. Последующие удары по другим
  целям не перезаписывают их. Повторные промахи луча по всем подходящим хитбоксам
  дают сигнал Hitbox. WallHit проверяет луч удара, а не линию к центру цели.
- NoSwing допускает анимацию после пакета атаки. BackTrack выбирает наиболее свежую
  подходящую позицию, исключая ложный флаг на неподвижной цели.

Это собственная консервативная модель движения и геометрии. Поддерживается
ограниченная копия отправленных клиенту чанков; всех механик Minecraft и переходов
между версиями протокола она пока не воспроизводит.

## Независимый симулятор физики

Добавлено отдельное Java-ядро `engine.physics`: перебор вариантов WASD, спринта,
прыжка и замедления, трение, гравитация, направленный импульс прыжка, столкновения
по AABB, скольжение вдоль стены и подъём на ступеньку. Атрибуты и поза игрока пока
берутся из Paper; геометрия строится исключительно по состояниям блоков из пакетов,
отправленных выбранному игроку. Ядро не обращается к Bukkit.

Это **диагностический профиль**, ещё не сверенный с живыми трассами клиента 26.2.
Его расхождения не добавляют VL/risk, не вызывают кики/баны и не заменяют Speed/Fly.
Для каждого наблюдаемого игрока хранится собственная копия мира в памяти:
загрузка/выгрузка чанков, одиночные и групповые изменения блоков. Обновления
применяются после ответа на служебный ping, отправленный вслед за ними.
До подтверждения затронутый участок считается неопределённым. Ломание и установка
блоков клиентом также исключают участок до подтверждения обработки действия сервером
и последующего pong. Этот порядок не доказывает честность клиента или точный тик
применения изменения — поэтому режим остаётся диагностическим.

Диагностика по умолчанию выключена. Для выбранного игрока:

```text
/vesuvio physics PlayerName on
/vesuvio physics PlayerName status
/vesuvio physics PlayerName off
```

После `on` перейдите в новую область или выполните дальний RTP: копия наполняется
новыми пакетами чанков. Уже отправленные до включения чанки не восстанавливаются из
серверного мира и принудительно не пересылаются. При `WAIT_CHUNKS` нужно дождаться
настоящей отправки нужных чанков сервером.

Одновременно допускаются четыре игрока. На игрока сохраняются до 32 ближайших
чанков, до 8 МиБ подтверждённых данных блоков и до 8 МиБ ожидающих данных, включая
данные в callbacks отправки. Это лимиты полезных данных; служебные Java-объекты
требуют дополнительную память. Геометрия одного замера ограничена 175 позициями
блоков и 512 AABB. Никаких загрузок чанков или создания Bukkit-миров нет.
Переключение диагностики очищает копию мира и кинематическую историю; агрегированные
счётчики симуляции сохраняются до выхода игрока. `toggle off` останавливает трекинг
и очищает копию, `punishment off` не мешает диагностике.

Поддерживается нативный клиент **26.2**. ViaVersion и другие версии возвращают
`UNSUPPORTED_PROTOCOL`. В каталоге форм: распространённые полные блоки, лёд,
полуплиты, прямые/угловые лестницы, заборы, калитки, стеклянные панели, решётки и
закрытые люки. Неподдерживаемые формы, жидкости и waterlogged-блоки дают пропуск.
`status` показывает число чанков, ожидающих обновлений, ping, действий клиента
и объём сохранённых данных. Причины пропуска выводятся отдельно:

| Статус | Значение |
| --- | --- |
| `MATCH` | Найден кандидат с ошибкой не более 0.03 блока |
| `MISMATCH` | Ни один рассчитанный кандидат не подошёл; это не вердикт о читах |
| `WARMUP` | Восстановление истории по первым двум позициям |
| `SERVER_TRANSITION` / `MOVEMENT_RESET` | Телепорт, импульс или смена режима; предыдущая история сброшена |
| `NO_POSITION` / `NO_ROTATION` | Недостаточно данных пакета |
| `TIMING_UNCERTAIN` | Интервал не попал в диагностическое окно 25–80 мс |
| `STALE_WORLD` | Снимок старше 150 мс, новее пакета либо относится к состоянию до сброса |
| `WAIT_CHUNKS` / `UNKNOWN_SECTION` | Сервер ещё не прислал нужные данные либо они удалены из ограниченного кеша |
| `WORLD_PENDING` | Геометрия участка изменяется; ожидается отправка или pong |
| `CLIENT_PREDICTION` | Клиент мог предсказать ломание/установку; ожидаются подтверждения |
| `WORLD_ACK_ORDER` / `WORLD_ACK_TIMEOUT` | Нарушен порядок ответов или превышены 5 секунд; копия очищена |
| `WORLD_QUEUE_LIMIT` / `WORLD_ACK_BACKLOG` | Достигнут лимит очереди; копия очищена |
| `UNSUPPORTED_PROTOCOL` / `UNSUPPORTED_SHAPE` / `UNSUPPORTED_STATE` | Версия, форма или механика пока не поддерживается |
| `OUTSIDE_SNAPSHOT` / `INCOMPLETE_GEOMETRY` / `WORLD_HEIGHT` | Недостаточно геометрии для расчёта |
| `CAPTURE_FAILED` / `WORLD_DECODE_FAILED` | Атрибуты или пакет не удалось прочитать |

Проверяйте ходьбу, повороты, прыжки, полуплиты, стены, низкий потолок и BetterRTP
отдельными сценариями. Пока профиль диагностический, существующие проверки могут
наказывать: для безопасного тестового прогона используется `punishment off`.

Спецификация, происхождение и ограничения метода белой комнаты:
[docs/physics-spec.md](docs/physics-spec.md). Исходники GrimAC не читались и не
переносились. Предшествующее изучение Vacan исключает заявление о полной
организационной изоляции clean-room; его разбор не использован как спецификация ядра.

Порядок обновления копии мира и оставшиеся ограничения:
[docs/client-world.md](docs/client-world.md).

## Проверка на сервере

Сборка и автоматические тесты не заменяют проверку взаимодействия с конкретными
плагинами сервера. Для первого прогона используйте `/vesuvio punishment off`:
проверьте BetterRTP, смену мира, возрождение, Haste/Efficiency, мгновенное копание,
обычный PvP и бой при задержке. Сопоставьте сообщения `[FLAG]` с действиями игрока;
для подробных значений включите `settings.debug` и выполните `/vesuvio reload`.
Живой сервер с BetterRTP в этой рабочей среде не запускался.

Статический разбор Vacan: [docs/vacan-analysis.md](docs/vacan-analysis.md).

### Потоки и русский интерфейс

Команды, объяснения нарушений, сообщения плагина в консоли, диагностика физики,
веб-панель и встроенные профили настроек переведены на русский. Идентификаторы
проверок, API/SQL/CSV, имена команд, моделей и материалов Minecraft остаются
стабильными. Локализованные подписи находятся в `messages_ru.properties`.
Существующие пользовательские конфиги и профили не перезаписываются: сохранённые
в них тексты наказаний при необходимости замените русскими из встроенных ресурсов.
Сообщения сторонних библиотек и исторические записи базы данных не переводятся.

Настройки в `settings` применяются после **перезапуска сервера**, а не `/vesuvio reload`:

```yaml
virtual-threads: true
max-background-tasks: 2048
inference-parallelism: 2
```

При `virtual-threads: false` используются ограниченные пулы обычных потоков.
Пакетные проверки сохраняют очередь каждого игрока (до 256 задач); общий исполнитель
ограничивает число принятых задач/обработчиков, включая ожидающих. При перегрузке
новая работа отклоняется без выполнения на сетевом или основном потоке сервера.
ONNX имеет отдельную очередь до 128 задач и лимит одновременных вычислений;
внутренние пулы ONNX ограничены одним потоком на вычисление. Пропущенное вычисление
завершается ошибкой и не подставляет нулевую вероятность в ансамбль.

Виртуальные потоки не ускоряют арифметику сами по себе. Они применяются к фоновым
задачам и ожиданию ввода/вывода. Атрибуты Bukkit по-прежнему снимаются на основном
потоке. Для физики сетевой поток фиксирует 175 идентификаторов блоков и версию
подтверждённого мира; построение коллизий и перебор движений выполняются в фоновой
очереди. При выключении исполнители останавливаются до закрытия базы и моделей;
обучающий процесс также завершается. Настройка лимитов требует замеров на конкретном
сервере; гарантии прироста TPS без нагрузочного теста нет.

### Сбор диагностики на честных игроках

После установки JAR и перезапуска сервера:

```text
/vesuvio punishment off
/vesuvio log on
```

Команда требует `vesuvio.admin` и пишет отдельную сессию в
`plugins/Vesuvio/diagnostics/diagnostic-<время>-<идентификатор>.log`.
`settings.debug` включать не требуется. Команда меняет только запись журнала;
режим проверок, наказаний, обучение и наблюдение новой физики не переключаются.

При срабатывании сохраняются причина и подробности проверки, показатели игрока,
транзакционный пинг и подтверждения, снимок окружения, интервалы кликов и изменения
прицела, отчёт физики (если она включена), до 20 последних событий телепортации,
добычи и отбрасывания, а также 20 снимков движения с интервалом 5 тактов.
Снимки дают около 5 секунд предыстории при 20 TPS; это выборочная история, а не
побайтовая запись всех пакетов. Поля контекста отражают состояние при сборе журнала,
результат проверки содержит непосредственно её диагностические данные.
В начале файла записываются версии сервера, Java, плагинов и настройки проверок
на момент включения. Журнал также отмечает срабатывания, отклонённые общей защитой
после телепортации. Чат, IP, токены, параметры подключения к БД и webhook не собираются.

После теста выполните `/vesuvio log off`, затем `/vesuvio log status`.
Дождитесь состояния «сохранён / выключен» и отправьте указанный файл.
При отсутствии срабатываний файл содержит начало и итог сессии.
Физика автоматически не включается; для её расширенной диагностики по-прежнему
используется `/vesuvio physics игрок on`.

Один файл ограничен 64 МиБ, весь каталог — 256 МиБ; существующие журналы не
удаляются и не перезаписываются. При достижении лимита файла запись останавливается.
При заполнении каталога новый запуск отклоняется: скачайте и перенесите старые файлы.
Фоновая очередь ограничена 256 записями, крупная запись сокращается после 32768
символов с отметкой в файле. Пропуски при перегрузке видны в статусе и итоговой записи.
По умолчанию после перезапуска запись выключена. Остановка сервера завершает журнал.

## LoveEssential: управляемые состояния игрока

Обновите **оба плагина** для полной интеграции. Vesuvio автоматически находит
`PlayerMechanicsService` через Bukkit и получает изменения сразу после успешного
действия. Дополнительное чтение раз в тик восстанавливает состояние при позднем
включении модуля. Жёсткой зависимости от LoveEssential нет; со старой версией
доступен только `DownedOracle` из LoveCore для состояния ранения.

| Механика LoveEssential | Что учитывает Vesuvio |
| --- | --- |
| Sit, Lay, Ride | Управляемую позу и геометрию тела |
| Revive | Ранение, поднятие/сброс с рук, начало/конец восстановления |
| Переносчик | Короткий переход при поднятии/сбросе; затем обычные проверки |
| Помощник при восстановлении | Управляемое движение; боевые проверки продолжаются |
| God | Фактическое серверное состояние, без проверки прав как основания исключения |
| Fly, Speed, смена скина | Короткую адаптацию после успешного изменения; дальше штатные способности/атрибуты |
| Home, Spawn, RTP, порталы, миры, путевые столбы | Штатные события телепортации и подтверждения teleport ID |

Период перехода — `integrations.loveessential.transition-ms` (по умолчанию 500 мс,
максимум 2000 мс с учётом RTT). Список `states` позволяет отдельно включать учёт
состояний. Vanish, права доступа, GUI, ожидание телепорта и декоративные эффекты
не дают постоянного исключения. Данные протокола проверяются отдельно.

На переходе сбрасываются старые координаты, тайминги, признаки прицеливания и
геометрия цели. Накопленные VL, риск и доверие сохраняются. Изменения Bukkit
читаются на главном потоке; обработчики пакетов получают неизменяемый снимок.
Состояния записываются в существующую диагностику срабатываний.

### Пинг и паузы клиента/сервера

Нулевой RTT на локальном сервере допустим. Blink требует подтверждённых быстрых
ответов **на протяжении самой паузы движения**; старого низкого пинга или серии
ответов после зависания недостаточно. История ограничена 256 образцами (примерно
4 КиБ полезных данных на подключённого игрока) и удаляется при выходе. Обычный
простой клиента и восстановление после зависания покрыты регрессионными тестами;
активность во время настоящего Blink продолжает обнаруживаться.

Эти тесты воспроизводят конкретные сценарии, но без исходного алерта нельзя
утверждать, что неизвестное срабатывание «про пинг» было именно Blink.
